## kkFileView-jdk1.8：sevenzipjbinding 按架构分包改造
- 问题：`server/pom.xml` 原把 `sevenzipjbinding` 核心 + `all-platforms` + `linux-arm64` + `mac-x86_64` 四个 jar 一起打进包。`all-platforms` 不含 arm64/mac-x86_64 的 native 库，同包后运行到对应架构时 sevenzipjbinding 会错误加载 all-platforms 同名 native 库，须手动删 jar。
- 方案：把平台 native 库移入 Maven `<profiles>`：`sevenzip-all`(activeByDefault，amd64)、`sevenzip-linux-arm64`、`sevenzip-mac-x86_64`。显式 `-P` 激活某 profile 时默认 profile 自动失效，故每个包只含对应 jar。
- 工作流：`.github/workflows/docker-image.yml` 与 `maven-publish.yml` 改为 matrix 按架构构建并产出 `dist/kkFileView-<arch>.tar.gz`；`Dockerfile` 用 `ARG TARGETARCH` + `ADD dist/kkFileView-${TARGETARCH}.tar.gz` 选对应产物，arm64 容器不再冲突。
- 本地构建：`mvn clean package -Psevenzip-linux-arm64`（arm64）/ `-Psevenzip-all`（amd64 默认）/ `-Psevenzip-mac-x86_64`。
- 注：仓库是从 https://github.com/jiangchuanso/kkFileView-jdk1.8 浅克隆到工作区的。
